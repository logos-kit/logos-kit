# Independent full review — Logos Kit

**Reviewed:** 2026-09-29, `main` at `34d7d8d`. **Scope:** code, plan, prize specification, local screenshots, live docs/catalog/endpoints, and the commands below. This is a review of the present artifact, not a submission certification. Status means **done**, **partial**, **missing**, **deferred-with-reason**, or **dropped-without-reason**. Evidence marked **V** was read or run in this review, **I** is an inference from that evidence, and **U** was not verified. Historical green results in `PROGRESS.md` are claims unless independently reproduced.

## Verdict

**A real, unusually deep Basecamp preview release; not the LP-0021 first release as defined, and not close to an eligible prize submission.** The Rust custody core, QML wallet, mini-apps, SDK, conformance fixture, signed catalog, and live v0.3 preview are tangible. I ran type/build checks, Rust checks, docs build, network fingerprints, and a live token flow. But the canonical endpoint still fingerprints as 0.2.x; the official on-chain testimonial count is zero as far as this review can establish; adoption tables are blank; the root README is a placeholder; this repo has no default-branch CI workflows; and the npm installation advertised on the docs landing page returns 404. Those are acceptance gates, not polish. The wallet UI has a credible Tray foundation, but approval hierarchy, keyboard accessibility, app/template cohesion, and docs are well short of the product vision. **V:** `../refs/lambda-prize/prizes/LP-0021.md:25-95`, `../docs/09-architecture.md:285-297`, `README.md:1-30`, `adoption/tracker.md:14-37`, `PROGRESS.md:331-339`; commands in §7. **I:** prize distance and UX judgment.

The official 0.3 release is outside this team's control. Its deferral is reasonable for a **preview**, not safe for calling §8 complete or starting the *official* two-month count. S9 CI, evaluator README, demo, and adoption work cannot remain behind a “first release” label if that label is meant to signal prize readiness. **V:** prize criteria and `docs/dev/PLAN.md:622-673`; official fingerprint in §7.

## 3. Forgotten or prize-critical gaps

1. **Official-chain launch gate is not an operational runbook.** `apps/docs/content/docs/networks.mdx:22-32` says “redeploy there” and `PROGRESS.md:337` leaves a checkbox. A cutover needs final LEZ pin and codec/vector validation, fingerprint and fee behavior, fresh program build/image verification, immutable deploy/registry update, official faucet backend selection, CLI/QML defaults, catalog version, docs, four-route real-proof tests, exporter snapshot, and rollback criteria. The preview's 0.3 fingerprint and real proving make it a good rehearsal; its chain ID and testimonials do not satisfy LP-0021. **V:** `../docs/09-architecture.md:297`, network fingerprints §7. **I:** rollout sequence.
2. **Evaluator and CI contract vanished behind S9.** No `.github/workflows/` in this repo, no green default-branch E2E, no `demo.sh` clean-machine contract, and `README.md:24-26` literally postpones instructions. The prize makes these explicit. Deferring S9 after an announced first release is unsafe. **V:** prize `Supportability` and evaluation paragraphs, `docs/dev/PLAN.md:622-643`.
3. **Adoption is still a blank program.** No verified independent Basecamp apps or official-chain monthly/Discord/X logs in `adoption/tracker.md:14-37`; the exporter is not running on a cadence. Preview usage cannot begin the official two-month window. Outreach drafts respect the maintainer's approval boundary, but drafts are not traction. **V:** tracker, `adoption/drafts/`, `testimonial.rs`.
4. **`other_txs` is not prior unrelated activity.** The exporter reads the account's *current* nonce and subtracts one (`testimonial.rs:371-384`). A user can post first and transact later and appear active; unrelated transactions are not identified. The prize specifically discounts first-use-only accounts. Fix before presenting adoption evidence. **V:** code and prize adoption paragraph.
5. **Gas used and balance buckets lack release evidence.** `FeeInfo.used` exists in schema, but the visible wallet approval offers a fee cap; no actual used value or spendable/pending/locked triplet was found in QML activity. The gas criterion is conditional on network availability; document the RPC limitation and show “unavailable” when it truly is. **V:** schema and `ApprovalView.qml:136-141`, `Home.qml:132-141`; **U:** official v0.3 availability.
6. **The web/mobile surfaces remain visible commitments.** S10–S15 contain React, RN and passkey work, so the plan did not silently drop them, but `README.md:3-7` and landing copy imply a product that already exists. React and RN are safely deferred for the LP-0021 Basecamp path; misrepresenting them is not. **V:** decision D1/D2, `docs/dev/PLAN.md:676-810`, `README.md`.
7. **Legacy S0/S1 tasks with no closing evidence:** design-system storybook (`PROGRESS.md:47`), upstream LEZ/CORS PR publication (user-owned or external; **U**), exhaustive clean Mac/Linux GUI validation (**U**), and scheduled evidence snapshots (no `adoption/snapshots/`). These are lower prize risk than the first four, but should be explicitly resolved or descoped.

## 6. New correctness and security findings

These are **new facts** relative to `docs/reviews/s8/codex-review.md`. I do not re-report its seven fixed bugs. I found no confirmed critical private-key extraction, grant bypass, sequencer halt API, path traversal in `ui_appInfo`, or arbitrary URL opening through `lez_openExplorer` in this review. `policy.rs` fails closed on untrusted callers; `tx.rs` binds the approval and guarded testimonial repage; `service.rs:2169-2235` bounds requester/path/PNG size and `service.rs:1531-1584` validates explorer targets and connection/rate budget. That is a scoped source inspection, **not** a security audit. No `e2e/standalone.sh` run was started, per the prompt's port guard. **V:** cited source.

| Rank | New finding, failure scenario and fix |
|---|---|
| **High** | **The public drip's 5/hour IP budget likely applies to the Traefik peer, not the end user.** `crates/logos-kit-drip/src/main.rs:84,125-137` trusts `X-Forwarded-For` only with `LK_DRIP_TRUST_PROXY=1`; `deploy/preview-net/docker-compose.yml:40-65` routes all public drip traffic through Traefik but omits that env var. `client_ip()` therefore uses the socket peer, likely the same Docker proxy for all visitors; `main.rs:139-155` and the live info endpoint show only five slots/hour. One small burst of claims can block unrelated users. **V:** code/config/live quota; **I:** shared peer IP under this deployment; live client IP was not observed. **Fix:** use a trusted, normalized client IP passed by a locked-down proxy with direct service access blocked; test claims from distinct external IPs, and set a documented global treasury budget too. Never blindly enable arbitrary client-supplied `X-Forwarded-For`. |
| **High** | **Faucet idempotency and per-account cooldown disappear on restart.** `crates/wallet-engine/src/faucet.rs:74-82,121-137,247-309` keeps the 24h request-key outcome and account timestamps only in process memory. A legitimate or hostile client can reuse the same key/account after a deploy or crash and receive a second drop; enough restarts could drain the preview treasury. An ambiguous payment across restart is especially unsafe to retry. **V:** implementation; **I:** restart/retry scenario. **Fix:** durable keyed ledger and atomic claim state, with reconciliation against chain before repaying; keep a separate cap on total funds. Also correct the absolute “never pays twice” docs statement. |
| **Medium** | **Adoption evidence overstates “prior unrelated activity.”** `crates/wallet-engine/src/testimonial.rs:371-384` samples the account's current nonce at export time and subtracts one; `:428-435` decides `target.met` without prior-activity quality. A testimonial posted as the account's first transaction looks “active” if any transaction occurs afterward, and the other transaction could itself be related. **V:** code; **I:** evaluator impact. **Fix:** reconstruct the author's transaction history *before the testimonial block*, classify unrelated calls, expose proof transaction/block IDs, and make the qualifier visible separately from raw 150/month counts. |
| **Medium** | **The template's unknown-outcome recovery can falsely report Done.** `templates/basecamp-dapp/qml/Main.qml:100-105,120-139` falls back from an included/unknown receipt to “any decrease in my balance since send” without checking the saved amount, destination, token or transaction's own effects. A concurrent spend or fee can make this unrelated transaction look successful. This is a narrower defect in the *new fallback*; the S8 bug of treating inclusion alone as success was fixed. **V:** code; **I:** concurrent-spend scenario. **Fix:** only confirm with a tx-specific event/receipt or a verified account invariant tied to the approved transfer; otherwise remain “unconfirmed.” |
| **Medium** | **Signing key is copied to a persistent temp path without cleanup.** `deploy/preview-net/entrypoint.sh:5-11` creates a 0600 file, then `exec`s the sequencer, so the script never unlinks it; `docker-compose.yml:10-12` also injects the signing key as an environment variable. No evidence the live key is committed, and container isolation limits exposure, but a process with container UID/filesystem access can read the leftover file and an operator may inspect the env. **V:** code; **I:** access scenario. **Fix:** use a secret file/ephemeral tmpfs and a wrapper that deletes the file after the sequencer opens it, or a supported FD/secret mechanism; ensure backup and container inspection controls match the threat model. |
| **Low** | **429 replies omit standard `Retry-After`.** `crates/logos-kit-drip/src/main.rs:171-199` serializes `retry_after_seconds` in JSON but returns only `(StatusCode, Json<Value>)`. The bundled client handles the JSON; generic callers may retry too soon. **V:** code. **Fix:** set the HTTP header from the same countdown. |

The unauthenticated public RPC and permissive CORS are intentional for a public test network (`docker-compose.yml:18-38`); Traefik sets a 20/s average, burst 60 limit, but I did not load-test or prove it prevents resource exhaustion. Genesis funds are explicitly public in `sequencer_config.json:21-34`; the `bedrock_config.funding_key` there points to loopback `127.0.0.1:18080` (`:8-12`) and should not be called a leaked live production key without more evidence. I examined tracked secret-looking paths and sampled `git log -p --all` candidates; no confirmed live private signing key/`.env` was found. A full credential-history audit and live server config review remain **U**. **V:** source and bounded search; **U:** operator secret stores/live process state.
